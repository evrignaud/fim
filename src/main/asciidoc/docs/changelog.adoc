=== General
* Fim is now built with **Gradle** instead of Maven, through the wrapper committed in the repository, so no build tool has to be installed
* Fim is now compiled with **Java 17** and requires Java 17 or later to run. The tests moved to JUnit 5
* The Docker image builds the Fim distribution itself, so it can be built from a freshly cloned repository with no JDK and no prior build on the host
* Building and checking Fim no longer depends on a hosted service.
  Travis CI, AppVeyor, Coverity Scan and Coveralls are replaced by `./gradlew check`, which compiles, tests, checks the style, runs **SpotBugs** static analysis and holds coverage to a floor, all on your own machine.
  Details in <<how-can-you-use-fim.adoc#_verifying_fim,Verifying Fim>>
* The same checks run on **Linux, Windows and macOS** through a **GitHub Actions** workflow for every push and pull request, so the tests that only apply to one platform finally run on it.
  The SpotBugs findings are published under Security, Code scanning, and the coverage figure appears in the summary of each run.
  Details in <<how-can-you-use-fim.adoc#_what_runs_on_github,What runs on GitHub>>
* A release is now done by a single script, `release.py`, which tags, builds, packages the release archives, builds the Docker image from the tag and prepares the commit that publishes the documentation.
  Details in <<how-can-you-use-fim.adoc#_releasing_fim,Releasing Fim>>

=== New features
* An interrupted `init` is now resumed instead of started again.
  Fixes https://github.com/evrignaud/fim/issues/27[issue #27]
** The hashes computed so far are kept, so stopping a long `init` with Ctrl-C no longer throws away its work
** The progress is saved as the `init` runs, so a machine that loses power resumes as well
** A file modified after being hashed is hashed again, so a resumed `init` never describes a file by a hash it no longer matches
** Details in <<faq.adoc#_pausing_and_resuming_the_init_of_a_big_repository,Pausing and resuming the init of a big repository>>
* Duplicate results can be ordered with the **`--sort`** option, on wasted space, number of files, file size, or file path.
  The **`--order`** option reverses the direction.
  Fixes https://github.com/evrignaud/fim/issues/12[issue #12]
** Sorting on `path` groups together the duplicates that live in the same directory
* Duplicate results can be restricted with the **`--include`** and **`--exclude`** options.
  Fixes https://github.com/evrignaud/fim/issues/11[issue #11]
* Duplicates can be reported in **CSV** or **JSON** with the **`--output-type`** option.
  Fixes https://github.com/evrignaud/fim/issues/14[issue #14]
* Details on all of these in <<dealing-with-duplicates.adoc#_dealing_with_duplicates,Dealing with duplicates>>

=== Bug fix
* Fix https://github.com/evrignaud/fim/issues/13[issue #13]:
  `rdup -M` applied the `.fimignore` files of unrelated directories when run from inside a Fim repository
* Fix https://github.com/evrignaud/fim/issues/16[issue #16]:
  Files of different lengths were reported as duplicates of each other
* Fix https://github.com/evrignaud/fim/issues/22[issue #22]:
  A duplicate that could not be deleted was reported as "Error deleting file", naming neither the file nor a reason.
  The failure now names both, and points at the locale when a file name cannot be represented by the encoding the JVM maps names with
* Fix https://github.com/evrignaud/fim/issues/23[issue #23]:
  The space a commit freed was reported one State later than the commit that freed it
* Fix https://github.com/evrignaud/fim/issues/24[issue #24]:
  Answering 'A' to a `rdup -y` prompt did not keep applying to the remaining questions
* Fix https://github.com/evrignaud/fim/issues/25[issue #25]:
  A repository could not be created on a CIFS/SMB share, because such a mount reports the permissions of the mount rather than those of the account in use.
  Fim now decides by trying rather than by asking
* Fix https://github.com/evrignaud/fim/issues/28[issue #28]:
  `docker build` failed on a freshly cloned repository, because it expected a distribution the host had not built yet

=== Documentation
* Thanks to https://github.com/evrignaud/fim/issues/20[issue #20], document how to create a `.fimignore` on Windows

=== Global improvement of the performance
* **Decrease the State size** in memory and on the disc by using Ascii85 instead of Hexa to store hash. Each hash string length is now 80 instead of 128.
* Add **Super-fast commit** support. See more in <<index.adoc#_super_fast_commit,Super-fast commit>>
* Allow to **manage a very big amount a files** (1 098 138 files is working for me)
* **Optimisation of the State comparison** to be able to compare quickly two States that contains 1 000 000 files

=== General
* Fim is now distributed as **Docker image** on Docker Hub. See more in <<how-can-you-use-fim.adoc#_run_fim_using_docker,Run Fim using Docker>>
* Add the **`--directory`** option to be able to specify where to run Fim commands
* Every commit on Fim is now tested on **Mac OS X** thanks to the Travis Mac builder
* Run static code analysis on **Sonar** and **Coverity**
* Add the **`--purge-states`** option that purge previous States if the commit succeed

=== Bug fix
* Check access rights for the `.fim` directory before executing every command
* Ignore the milliseconds for date modification comparison because some JDK don't retrieve them and set them to 0
* By default truncate output to 200 lines of the same kind. `--output-max-lines` option added to modify this
* Empty files are not seen as duplicates

=== Migrating from 1.1.0 to 1.2.0

State format is modified and not compatible. You need the rehash the complete repository. +
To migrate type:

[source, bash]
----
$ fim ci -y -c "Migrate to Fim 1.2.0"
----
